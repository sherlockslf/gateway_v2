# OpenAI-Compatible Adapter

## Purpose

`usig-adapter-openai-compatible` adapts OpenAI-style Chat Completions, Responses API and Images streaming endpoints into the USIG `GatewayEvent` contract.

## Capabilities

| Capability | Status | Notes |
|---|---|---|
| streaming | supported | Parses SSE `data:` frames from Chat Completions, Responses API and Images streaming streams. |
| cancel | supported when configured | Optional `cancelEndpointTemplate` issues a downstream POST using `{downstreamRunId}`. |
| resume | supported when configured | Optional `resumeEndpointTemplate` issues a downstream POST using `{downstreamRunId}` and gateway cursor, then maps the returned SSE stream. |
| replay | gateway-owned | Replay is handled by `RunEventPublisher`/`ReplayStore`, not by this Adapter. |
| taskQuery | supported when configured | Optional `queryStateEndpointTemplate` issues a downstream GET and maps status text to `DownstreamExecutionState`. |
| humanInput | supported when configured | Optional `submitInputEndpointTemplate` issues a downstream POST using `{downstreamRunId}`; otherwise `submitInput` fails explicitly. |
| multimodalInput | supported by service capability | Text and image URL input can be mapped; application use cases reject image input before execution when the service does not declare multimodal support, and validate image refs as HTTPS URLs without localhost/IP-literal hosts, DNS-resolved private hosts, service-level host allowlist misses, redirects, over-limit content length, unsupported/mismatched MIME types or mismatched JPEG/PNG/GIF/WebP content signatures before the Adapter is invoked. Default URL probing uses HEAD metadata first, then a bounded Range sniff; when HEAD is unsupported or omits metadata, a 206 Range response must prove total size via Content-Range. Clients can also request a service-scoped image upload credential through the service API and confirm upload completion against the local signed record; the current bootstrap issuer is a local presign/callback boundary that returns upload expiry and configured retention expiry and can clean expired local signed records, but does not claim product object-storage signing, callback verification or cloud object lifecycle deletion. |
| structuredOutput | not specialized | Raw downstream structured protocol is converted only through supported event families. |
| retrySafety | NONE | Create/resume retry safety is not declared until product-level idempotency and source cursor semantics are verified for the downstream service, so the gateway will not retry create execution or resume for it. |

## Credential Boundary

- Bearer tokens are provided by `OpenAiCompatibleCredentialProvider`.
- `SecretStoreOpenAiCompatibleCredentialProvider` reads from an `OpenAiCompatibleSecretStore`.
- `EnvironmentOpenAiCompatibleSecretStore` checks `USIG_OPENAI_TOKEN_{TENANT}_{SERVICE}` first, then `USIG_OPENAI_TOKEN_{SERVICE}`.
- `VaultKv2OpenAiCompatibleSecretStore` can read Vault KV v2 JSON from tenant-scoped `/{mount}/data/{tenantId}/{serviceId}` first, then service-scoped `/{mount}/data/{serviceId}` fallback, using `X-Vault-Token` and a configurable token field.
- `KmsDecryptingOpenAiCompatibleSecretStore` can wrap an encrypted Secret Store and decrypt its value through `OpenAiCompatibleKmsDecryptor`; `HttpKmsOpenAiCompatibleDecryptor` posts ciphertext plus tenant/service context to a configured decrypt endpoint and reads a configurable plaintext field.
- Tokens are injected only into the configured auth header and must not be written into request bodies.

## Contract

- Adapter output is always `GatewayEvent`; OpenAI raw chunks are not exposed to clients.
- Chat Completions `delta.content`, tool arguments, usage and `[DONE]` are mapped into stable gateway events.
- Responses API response lifecycle with downstream response/event metadata, output item lifecycle with downstream response/event metadata, output text delta/done with downstream response/event metadata, item/content indexes and optional logprobs, content part lifecycle with downstream response/event metadata including unknown part fallback, output audio delta/done, output audio transcript delta/done, refusal delta/done with downstream response/event metadata, reasoning text delta/done and reasoning summary text/part with downstream response/event metadata, function call arguments and custom tool input with downstream response/event metadata, function/custom/computer/shell tool lifecycle, computer call output screenshots and acknowledged safety checks, shell call output results, built-in file/web/code interpreter/MCP/image generation tool status, file/web search status and failed/incomplete tool errors with downstream response/event metadata, code interpreter status/code chunks and failed/incomplete tool errors with downstream response/event metadata, image generation status/partial images and failed/incomplete tool errors with downstream response/event metadata, MCP arguments events with downstream response/event metadata, MCP `calling` progress and `incomplete` error status with downstream response/event metadata, MCP list-tools lifecycle/error status with downstream response/event metadata, MCP approval request/response items, output text annotations with downstream response/event metadata, usage, completed and terminal error events with downstream response/event metadata are mapped into stable gateway events.
- Images streaming `image_generation.partial_image` is mapped into `ARTIFACT_UPDATED`, preserving partial image index, Base64 image data, creation time, background, output format, quality and size without inventing Responses-specific metadata.
- Unknown future Responses API `response.*` events are preserved as `EXTENSION` events with `extensionType=response.raw`, downstream response/event metadata, selected item/index metadata and the original JSON payload under `rawEvent`; unknown `response.content_part.added/done` part types are preserved as `EXTENSION` events with their part type and raw part object; this prevents silent drops while leaving dedicated semantic mappings for future slices.
- Responses API `response.failed` and `response.incomplete` preserve response status, response id, error details and incomplete details on `EXECUTION_FAILED`.
- Supplemental input and approval payloads can be forwarded to a configured downstream endpoint; approval payloads that contain `approvalRequestId` must include a non-blank approval request id and boolean `approve` value before Adapter forwarding. The request body preserves gateway `runId`, `tenantId`, `downstreamRunId` and the client `payload`.
- Resume can be forwarded to a configured downstream endpoint; the request body preserves gateway `runId`, `tenantId`, `downstreamRunId` and gateway cursor. The gateway resume context must include `conversationId` so resumed events keep the original conversation. Gateway-level resume retry remains disabled unless the service explicitly declares `RESUME_SAFE`.
- Downstream open timeout, first gateway event timeout, idle event timeout, total execution timeout and cancel timeout are configured independently.
- Timeout failures expose stable gateway `ErrorCode` values for connect, first event, idle event, total execution and cancel timeout paths.
- Downstream HTTP errors and invalid stream frames fail explicitly.
